# Дуэли Android ↔ Android, этап 2

Разработка в `feature/local-duels`, без публикации. Тестовая версия `2.0.0-prototype.1`, versionCode 13; прежние applicationId и сертификат.

## Устройство хоста

`DuelHostPlugin.java` — Capacitor-плагин с нативным WebSocket-сервером [Java-WebSocket 1.6.0, MIT](https://github.com/TooTallNate/Java-WebSocket). Node.js на телефоне не используется. Сервер связывается только с частным IPv4 интерфейса wlan, выбирает свободный порт ОС, принимает `/duels`, ограничивает число соединений, размер кадров и частоту сообщений.

Плагин передаёт сообщения в `android-host.ts`, который запускает существующий `DuelRooms` из `room-server.ts`. Проверки решений, готовность, общий старт, счёт, реванш и токены возврата общие с ПК-сервером. Ни Java-копии правил головоломки, ни передачи победы «на доверии» нет.

Хост работает только с открытым приложением. При выходе из комнаты, остановке Activity или её уничтожении сервер и объявление сервиса закрываются. Фонового сервиса нет. Уход хозяина в фон завершает его сетевую сессию; восстановление после смерти процесса не предусмотрено.

## Подключение

На первом телефоне: «Дуэли Моти» → «Создать комнату». На втором: ввести код → «Присоединиться». Поиск выполняется через Android NSD/DNS-SD, сервис `_hexanexus._tcp.`, имя `Hexanexus-<код>`. [Описание Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd).

В «Настройках подключения» можно указать `IP:порт` вручную, в том числе для прежнего ПК-сервера. При заполненном адресе используется он, при пустом — телефонный хост/поиск. Код сам по себе не заменяет сетевое обнаружение; телефоны должны быть в одной Wi-Fi-сети без изоляции клиентов.

Разрешение — существующее `INTERNET` в тестовом манифесте. Геолокация, сканирование SSID, Bluetooth, USB и постоянно работающие службы не добавлены. Target остаётся 36; Android 17 и будущие требования LAN-разрешений нуждаются в отдельных проверках при смене target. Кубки по-прежнему не начисляются.

## Данные устройств

- A55: SM-A556E, Android 17, Wi-Fi `192.168.0.102`, ADB GUID `R5CX83B7N8D`. Свежая резервная копия перед изменениями: `.tools/a55-android-host-before.tar` и JSON. Контрольная точка — 280 гексиков, кампании 30/30 и 19/30.
- A32: SM-A325F, Android 13, Wi-Fi `192.168.0.109`, ADB GUID `RF8RC10KEMJ`. До установки пакет отсутствовал. После первого запуска создан стандартный новый профиль: 50 гексиков и незавершённое обучение. Для автоматизированных дуэлей обучение обходится только во временной копии хранилища в памяти; настоящий профиль не редактируется.

До добавления Android-хоста повторно проверены реальные ПК ↔ A55: матч 2:1, реванш 0:2, переподключение, равенство всех ключей сохранений. Для следующего теста Node-сервер на ПК остановлен; ADB используется по Wi-Fi исключительно для диагностики/касания, не как игровой транспорт.

Выявлена и исправлена ошибка настройки `Draft_6455`: пустой список подпротоколов отвергал обычный RFC6455 handshake. Сохранён лимит 8192 байта и добавлен стандартный пустой подпротокол.

## Выполненные проверки

На итоговом APK проведены два полных матча реальных телефонов: A32-хост → A55 и A55-хост → A32, оба по три раунда со счётом 2:1. Проверены одинаковые задания, общий старт, согласованный результат, запуск реванша, принудительный обрыв WebSocket гостя, возврат с токеном и выход обоих участников. Комнаты находились автоматически по коду через NSD. Адреса проверенных серверов: `192.168.0.109:32923` и `192.168.0.102:35133` (новый запуск выбирает другой свободный порт). Отчёт: `artifacts/android-duels-real.json`, скриншоты `artifacts/android-duel-*.png`.

Node-сервер на ПК во время этих матчей был остановлен, ADB reverse не использовался. Касания выполнялись через DevTools настоящих Android WebView по Wi-Fi ADB. Это не моки телефонов; ПК был только инструментом автоматизации и не передавал игровой трафик.

Отдельно проверена остановка нативного слушающего сокета при уходе A55 на домашний экран: `artifacts/android-host-lifecycle.json`. После первого матча устранено позднее событие остановки, которое могло повторно открыть комнату поверх главного меню.

589 TypeScript-тестов, 2 Java-теста handshake, TypeScript-check, production build и Android build успешны. В Java-тест включён обычный handshake без подпротокола, воспроизводящий найденную ошибку настройки сервера.

После установки и двух матчей все нативные ключи сохранений каждого телефона сравнивались с его исходным состоянием: различий нет. A55 — 280 гексиков, 30/30 и 19/30. A32 — 50 гексиков, 0/30 и 0/30, настоящее обучение остаётся незавершённым. Отчёт: `artifacts/android-duels-final-audit.json`.

Итоговый APK `release/Hexanexus-v2.0.0-prototype.1-test.apk`: 52 710 448 байт; SHA-256 `5ee4c9659bfa7d7e4c8a27edf5556a5f3bd1dd81b4d995752dfe445393235b85`. Хеш файла на обоих телефонах совпал с локальным, сертификат прежний, versionCode 13.

Остаётся ручная проверка физического выключения/включения Wi-Fi и игры после отсоединения кабелей/прекращения диагностики. Разрыв WebSocket не выдаётся за проверку реального отключения Wi-Fi. Публикация, тег и push не выполнялись.

## Повторное подключение после реального Wi-Fi-обрыва

Ручная проверка выявила сбой: A55 корректно прервал матч, A32 остался на «Связь…». Диагностика A32 после восстановления ADB показала шесть закрытых сокетов, устаревшее состояние `playing` и скрытую на другом экране надпись об исчерпании попыток. У клиента было только пять быстрых повторов, а окончательная ошибка не передавалась UI как завершение сессии.

В `client.ts` повторы ограничены временем 25 секунд вместо числа быстрых отказов; успешное получение сессии сбрасывает срок. При окончательной неудаче отправляется `closed`, интерфейс убирает поле/оверлей и показывает экран подключения. Серверное окно возврата гостя остаётся 30 секунд, правила матча не менялись. Два новых теста проверяют восстановление после более пяти отказов и окончательное завершение без висящих таймеров. Теперь 591 TypeScript-тест и прежние 2 Java-теста.

По отдельному явному поручению пользователя A32 превращён в постоянный тестовый профиль: обе кампании 30/30, обучение пройдено, 9 подарочных костюмов плюс классический и две кампанийные награды (всего 12). Резервные копии до изменения: `.tools/a32-before-unlock.json` и `.tools/a32-before-unlock.tar`. Игра автоматически начислила достижения за завершённые кампании: баланс 1450. Эти изменения не распространялись на A55 и не добавляют режима разблокировки в код игры.

На обновлённой сборке подтверждены 7 попыток соединения за 11 секунд эмулированного отсутствия сети на реальном A32, затем возврат того же участника и запуск реванша. При более длительном отсутствии сети интерфейс корректно вернулся на экран подключения без оверлея «Связь…». Это сетевая эмуляция DevTools, физическое выключение Wi-Fi требует повторного ручного теста. Отчёт `artifacts/android-reconnect-qa.json`. В гардеробе A32 проверены 12 карточек и ноль закрытых.

Текущий APK после исправления переподключения: 52 710 520 байт, SHA-256 `823739abc6a8286cd4327280fc548f98021566ae8b2a8ecdc78f2674373a216e`. На обоих телефонах установлен этот файл; A55 остался 280/30/19, A32 сохранил разрешённое тестовое состояние 1450/30/30.
