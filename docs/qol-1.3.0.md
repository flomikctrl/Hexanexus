# Android Back, инерция и оптимизация лобби — Hexanexus 1.3.0

Локальная тестовая доработка, версия 1.3.0 / Android versionCode 4. applicationId и исходный сертификат сохранены. Кампания, экономика, достижения, скины, музыка, рекорды и правила кубиков не изменены. Push, коммит, новый тег и публикация не выполнялись.

## Android Back

Установлен официальный `@capacitor/app` 8.0.0, совместимый с Capacitor 8.6. Вместо собственного Java callback с 700-миллисекундным тайм-аутом используется одно событие `backButton`. Тайм-аут мог передать обычное действие в стандартную обработку и завершить Activity, если WebView отвечал поздно. Этот обходной путь удалён; жизненный цикл прежней автопаузы оставлен.

Единый `BackNavigation` закрывает модальные окна, затем дополнительное меню; возвращает уровни, достижения и мастерскую в главное меню; в игре открывает паузу. Из мастерской Back возвращает домой с любой вкладки, вкладки по-прежнему переключаются своими кнопками. Настройки из паузы возвращаются в ту же паузу. Back из паузы кампании продолжает игру; в бесконечном режиме вызывается тот же `resume()`, что у кнопки продолжения, без создания второго таймера. Back из результатов бесконечного режима возвращает домой.

В главном меню первый системный Back показывает небольшое «Нажмите ещё раз для выхода». Второй в пределах 2000 мс вызывает `App.exitApp()`. После истечения времени снова требуется два нажатия; при смене экрана, закрытии окна и паузе/возобновлении приложения ожидание сбрасывается. Escape в браузере не вызывает выход. Не используются произвольные свайпы страницы: жест обрабатывает Android и передаёт его через Capacitor.

`AndroidBackBinding` регистрируется один раз при запуске, независимо от количества переходов по меню. Его `pause`/`resume` также останавливают рендер и сбрасывают инерцию. При уничтожении снимаются подписки. Установленный API проверен по локальному исходнику и [документации Capacitor App v8](https://capacitorjs.com/docs/apis/app).

## Волчок вокруг Y

`LobbyRotation` теперь меняет только yaw; pitch и roll декоративной группы равны нулю. Вертикальный компонент движения игнорируется, камера не двигается. Управление головоломкой через OrbitControls не менялось.

Угол следует за горизонтальным движением с чувствительностью 0,008 рад/пиксель. Скорость оценивается по последнему горизонтальному перемещению и времени события, сглаживается с постоянной времени 45 мс и ограничена 5 рад/с. Если палец остановился до отпускания, устаревшая скорость затухает и не создаёт ложного сильного броска.

После отпускания применяются аналитические формулы экспоненциального торможения: `v(t)=v0*exp(-3*t)`, `deltaYaw=v0*(1-exp(-3*dt))/3`. Это не фиксированное приращение на кадр; тесты при 30/60/120 FPS дают одинаковый результат. При скорости меньше 0,015 рад/с инерция заканчивается, затем выдерживается 900 мс паузы и плавно восстанавливается спокойное автовращение 0,13 рад/с в направлении последнего жеста. Типичный заметный бросок затухает примерно за 1–2 секунды.

Новый контакт прерывает прежнюю инерцию. `pointercancel`, потеря захвата или фокуса и сворачивание сбрасывают скорость. Обычная потеря pointer capture после корректного отпускания не отменяет только что созданную инерцию. При reduced motion остаётся ручной поворот, а движение после отпускания и автоматическое вращение отключены.

## Что вызывало рывки и что изменено

В прежнем коде был явный предел 30 FPS для меню. В сочетании с дискретной частотой RAF это давало длинные интервалы; на A55 получено около 22,6 отправленного WebGL-кадра/с. Также девять декоративных Mesh и девять отдельных контуров рисовались раздельно, а кубики отбрасывали тени в карту 2048×2048, хотя в лобби нет объектов, принимающих эти тени. Получалось 29 draw calls на основной кадр с учётом теневого прохода.

Изменения:

- Девять тел объединены в один `InstancedMesh`, все контуры — в один LineSegments. Форма, материалы и позиции сохранены. Вместе с кольцом и частицами это четыре draw calls.
- Тени в меню отключены; в игровой сцене они возвращаются. Лишний теневой проход исчез без изменения вида лобби.
- Снят предел 30 FPS. Рисование следует за RAF в одном `FrameLoop`; повторный `start()` не создаёт новую цепочку.
- Лобби ограничено pixel ratio 1,5, игровая сцена сохраняет прежний предел 2. Неизменный размер/ratio повторно не выставляется, чтобы не переразмещать буфер без необходимости.
- В статическом лобби не обновляются OrbitControls и подсказки игровой сцены. Частицы тоже используют deltaTime.
- `draw()` вне игры/редактора больше не пересобирает невидимые игровые кубики при каждом переходе по разделам.
- Геометрии и материалы создаются при инициализации и переиспользуются. Новые сцены при входе в лобби не создаются.
- При скрытом документе и Android pause RAF отменяется; после resume начинается одна цепочка без накопленного большого deltaTime.
- `Scene.dispose()` отменяет RAF, ResizeObserver и обработчики, отключает OrbitControls, освобождает геометрии, материалы, текстуры, теневые карты, instance buffer и renderer. HMR использует этот путь.

Геометрии каждый кадр не создавались и до оптимизации: измерение показало ноль новых вершинных буферов в обоих устойчивых прогонах. Дублирования WebGL-контекстов также не обнаружено. Основные найденные затраты — ограничение кадров, тени, отдельные draw calls и лишняя работа при UI-переходах.
